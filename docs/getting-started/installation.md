# Installation

This project already carries the documentation dependencies needed to build the site. A single Python environment is enough for development, testing, and docs generation.

## Local setup

```bash
python -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -e ".[dev]"
```

This install also brings in `tyro`, which powers the autogenerated command-line interface exposed by `run.py`.

Verify the environment before starting longer runs:

```bash
pytest
mkdocs build
```

`pytest` runs the default CPU-oriented suite. Additional compliance and benchmark suites are documented in [Testing and CI](../development/testing-and-ci.md).

## Optional GPU support

The runtime backend uses NumPy by default and switches to CuPy when `cfg.compute_engine.use_gpu = True` and CuPy is available. If CuPy is missing, the code falls back to CPU execution.

Recommended workflow:

- Start with a CPU install and validate correctness first.
- Add a CuPy build that matches the CUDA toolkit on the target machine.
- Re-run the compliance or benchmark suites on GPU hardware before trusting production-scale timings.

## Optional example HPC pipeline

The repository also contains a Slurm-oriented example pipeline in `src/polariton_hpc_pipeline/`. It is an application built on top of `polarism`, not part of the package itself. The intended entry point is the submission script inside that directory.

Typical cluster workflow:

```bash
cd src/polariton_hpc_pipeline
python -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -e "../..[dev]"
bash submit.sh --config config.yaml
```

On module-managed systems, load the site-specific Python and CUDA stacks before creating the environment. The bundled Rysy notes mention module names such as:

```bash
module load common/python/3.13.2
module load gpu/cuda/12.1
```

Check `module avail` on the target cluster before hard-coding those names.

## Required pipeline inputs

For the Slurm pipeline, make sure these files are set up before submission:

- `src/polariton_hpc_pipeline/config.yaml` for the experiment definition.
- `src/polariton_hpc_pipeline/slurm.env` for scheduler resources.
- `lasers_setup.yaml` or another laser YAML referenced by the config.

The pipeline creates a timestamped run directory with configuration snapshots, HDF5 outputs, metadata JSON files, and generated plots.
